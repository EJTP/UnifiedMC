# Remote control

The server mod can accept changes over HTTP: add a mod, remove one, re-read what is on disk.
That is a write endpoint on a game server, so the rules come first.

## Threat model

The port is reachable by anyone who can reach the game. Assume it is scanned. The endpoint
must be safe against someone who has the address and nothing else, and it must not become a
way to run code on the host.

## Rules

**Off unless configured.** No token in `unifiedmc.properties`, no write endpoint at all - not
a default token, not a warning, simply absent. A feature that is on by default is on for
people who never read this file.

**Token, compared in constant time.** At least 32 characters, generated by the CLI. A
`String.equals` on a secret leaks its length and prefix through timing; `MessageDigest.isEqual`
does not.

**Localhost or a token, never neither.** Panels usually give one allocated port, so binding to
localhost alone would make this useless over SFTP-only hosting. The token carries it instead,
and the config can restrict to loopback for anyone who tunnels.

**Writes land in `unifiedmc/`, nowhere else.** The endpoint takes a filename, never a path.
Anything with a separator or `..` is refused before it reaches the filesystem. It cannot write
to `mods/` directly either - that is what a restart is for.

**Uploads are verified.** A jar arrives with its expected SHA-1; a mismatch is discarded. This
is not about trust, it is about a truncated upload leaving a corrupt jar the server then tries
to load.

**Nothing is executed.** No restart command, no shell, no plugin loading. The endpoint changes
files; the panel restarts the server. Those stay separate jobs.

**Rate limited and logged.** Failed attempts are slowed down and written to the server log with
the source address, so a scan is visible rather than silent.

## What it cannot do

Restart the server, read arbitrary files, change `server.properties`, or touch anything outside
`unifiedmc/`. If you want those, use SFTP - that is what it is for, and it already has real
authentication.
